### 当前权重怎样确定

共用入口通过 `model_registry.current(task)` 取权重，`paths.model_weight` 也转到该函数。有 `models/current.json` 中的任务登记时，读取登记路径并核对指纹；无登记时使用代码中的DEFAULTS。

CNN默认回退可指向具体历史版本，不等于发布别名。获授权部署时使用 `models/cnn/digit.pt`、`models/cnn/choice.pt`，保留历史版本。不能修改DEFAULTS绕过部署授权。

crop.py在执行时解析current('m1')并记录实际路径、指纹，导入时不解析。基础权重位置由paths.pretrained提供。

## 4. 保存进度和验证约束

| 要查看或修改什么 | 实现文件 |
|---|---|
| 历次对比结论与文字证据 | `models/对比/<模块>/<批次>/`；结论、JSON/CSV、提示词和纠正记录保留。第二轮已删除图片、网页与中间脚本，历史HTML/图片链接不再可用，见`models/对比/README.md` |
| M1/M2独立固定验证身份 | `data/m1/validation_baseline.json`及`data/m2/validation_baseline.json`；`yolo_snapshot.validation_names`校验原名单和指纹，清理报告副本仅作证据 |
| 原始扫描已清理后的裁图校验、M4移除回归 | `pipeline/tests/test_cleanup_compat.py`，仅使用显式临时假库 |
| 01结构校验、并发保护、阶段事件和交接快照 | `tools/写快照.py` |
| 交接的结构、归档、重复提交、失败重试和目录约束回归 | `tools/验证交接与准入.py`，仅写临时假项目 |
| 当前CNN日志准入、快照读取和分区回归 | `pipeline/tests/test_data_flow.py` |
| 改造前的边界、CNN准入及前端测试 | `pipeline/tests/legacy/`，只供追溯 |

测试产物放在D盘带时间和codex的临时目录。交接回归用模拟项目，数据回归用假数据；通过这些检查不表示真实浏览器操作或完整训练已经验收。

## 5. 哪些入口不能继续使用

以下退休脚本保留在原有目录，继续由原位停止保护拒绝执行旧写入流程；不另建归档文件夹。现行训练快照统一使用`tools/迭代.py snapshot`，支持m1/m2/m3/digit/choice。共享模块的停止接口及退休兼容测试按原位置保留。

| 入口或功能 | 应怎样处理 |
|---|---|
| m1至m3的build_dataset.py | 旧写入入口已停止；改用统一snapshot |
| m2/build_snapshot.py、common/dataset_builder.py及fixed_dataset的旧构建函数 | 已停止旧构建；脚本及共享停止接口原位保留，部分纯函数仅供追溯 |
| CNN的build_digit_dataset.py、build_digit_legacy.py、build_choice_dataset.py | 历史生成脚本已停止，不能强行恢复写入 |
| tools/补多选区样本.py | 旧补样入口已停止 |
| common/choice_events.py及退休的数据/前端绑定场景 | 改造前的实现或断言，现行流程不调用 |
| CNN独立泛化测试 | choice已有`eval_choice.py`同名单比较；固定val参与选模，不能冒充独立测试 |
| 实际计分 | 本轮仅验收识别，标准答案JSON生成、评分和成绩导出后接 |

数据目录层次见[00的CNN目录说明](00-数据与命名规范.md#cnn数据目录怎样区分)。当前批次、准入数量、实际部署与实验候选统一记01。需追溯旧命令或决定时读[06](06-历史.md)，使用前重新核对是否仍适用。

历史权重改名与哈希对照：`models/weight_renames.json`；旧日志中的名称按此表追溯。
