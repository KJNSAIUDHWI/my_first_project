# 退休操作手册（2026-10-30机制迁移前）

仅追溯工具细节和旧阶段参数，不作为当前授权或默认操作。通用用法以05为准。

# 迭代操作

用户说明要解决的问题，代理按本手册准备和执行。用户不需要自己拼命令、填写内部字段或维护交接编号。

一轮工作的顺序是：**定目标 → 准备图片 → 人工审核 → 检查并冻结 → 训练留档 → 比较 → 决定部署。** 已完成的步骤可沿用已核实的记录，不必从头重跑。

本手册写通用方法。[01](01-接力记录.txt)写当前批次做到哪；[00](00-数据与命名规范.md)定义数据规则；[02](02-文件导航.md)用于找代码。

## 1. 先确定这一轮要解决什么

代理从用户需求和01中明确四件事：改哪个环节、针对什么错误、使用哪些数据、怎样判断改进。再核对旧模型和共同评估范围，决定本次应从哪一步开始。

| task | 处理什么 | 数据准备时特别注意 |
|---|---|---|
| m1 | 整页区域检测 | 阶段、父页名单、固定验证集 |
| m2 | 选择题内部检测 | 阶段、裁图来源、固定验证集 |
| m3 | 填空题内部大题框与大题号 | 显式已审批次、继承身份；每轮冻结验证，下一轮可按规则扩入新审val |
| digit | 题号识别 | 图片、数字标签与人工确认 |
| choice | 涂黑组合识别 | 答题行审核与特殊决定 |

统一迭代入口支持上表五项。其他环节不能靠更改task名称套用命令。

下面的命令均在项目根目录的PowerShell中执行。代理填写已核实的值；Read-Host只是人工运行时的输入示例，不是要求用户逐项填写。

```powershell
$python = 'D:\Dev\Python\3.13.6\python.exe'
$task = Read-Host '本轮任务：m1/m2/m3/digit/choice'
if ($task -notin @('m1','m2','m3','digit','choice')) { throw '任务名称不支持' }
$purpose = Read-Host '本轮用途'
$run = $task + '_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '_' + $purpose
```

run是这一轮训练目录的名字。接着已有快照工作时，直接使用01中的实际run，不新建空目录。

参数分三类处理：**本轮输入**来自用户需求和01；**固定清单**如sampling、splits和验证基线只读引用；**训练默认值**由统一入口提供，确需调整时先明确方案。

### 一个阶段收尾后怎样进入M3

先记录用户接受的效果范围、实际部署与候选、已知遗留问题，再准备M3。严格逐题全对的报告门槛和用户决定进入下一阶段分别记录，原报告不改成“通过”。少量CNN误差或待修手标可保留为后续问题，不要求反复重训才能继续。

M3负责从填空题区找“大题框5、大题号6”。先核对父页、方向、裁区覆盖和固定分区；`cascade/crop.py`只裁M2，不能用它直接生成M3。具体批次与就绪状态看01。

**数据范围。** snapshot显式给`--subset`已审名单，原stage0可用`--stage 0`。训练累计接入此前准入和新增普通已审图；坏训练标签用`--skip-invalid`留据排除，坏验证或请求名单中的未审图仍停止。验证每轮冻结前按[00第5节](00-数据与命名规范.md#5-哪些数据可以进入训练)登记全部普通已审合法val，保留原名单历史与父页身份。下一轮扩入新审val后，旧模型必须在同一新快照重评，训练中不改名单。

**起点与输入。** M3使用YOLO11s、1024方形补边、batch4；训练、独立评估和预标注统一`rect=False`。训练显式`--initial`指向官方底座或永久候选；n升级s时选择官方`models/pretrained/yolo11s.pt`建立s架构，不拿旧n当s续训。旧n候选及其640工作规格保留。reg_max32结构和迁移参数见下一节，部署另行授权。

**设备与数值。** 统一train支持`--imgsz`、`--device`、`--workers`（0为主进程加载）。GPU异常先用独立算子或短训复现；`--no-amp`、`--deterministic`用于全精度对照。已复现错误的FP32路径不盲目长跑，可经核查选择AMP或隔离运行时。保留模型、损失、BN、梯度、优化器和EMA保护；AMP溢出跳过更新与EMA并降scale，记录次数和轮次，不冒称正常更新。核对实际训练子进程的Python/PyTorch/CUDA/cuDNN，不能用监督进程环境代替；按用户指定设备执行，GPU失败不自行改CPU长训。


## 2. 准备图片和预标注

M3 当前 s/1024 候选训练采用方形补边（rect=False）；预标注及用于选择阈值的逐图预测也必须显式使用 rect=False，并把该参数记入预测审计记录。默认最小矩形补边已在实际物理样本复现大题框漏检，不能只核对 imgsz 相同。修改输入处理时，比较真实错例和固定验证，不能仅凭固定小验证集通过判断全量效果。

M3第十二版开始使用 `pipeline/m3/yolo11s_regmax32.yaml`，通过训练入口 `--model-config` 配合 `--model models/pretrained/yolo11s.pt` 从官方权重迁移匹配参数；框回归头扩大到reg_max=32，不恢复旧优化器。原默认reg_max=16、最大stride32时单框最长边上限960像素，小于1024输入，已在横跨图片的大题框复现93.75%宽度饱和；不能靠继续堆相同样本解决该上限。新权重须核对实际检测头reg_max=32，训练、独立评估和预标注继续1024/rect=False；旧候选按原结构保留，不改装旧权重。

M3预标注另有计算稳定性准入：2026-10-29第十三版530张暂存结果中6张出现46至300个异常框；同权重、同参数重新GPU推理3次均恢复8或12框，与CPU FP32参照坐标差小于0.000001。此类输出虽然数值有限、框在图内，也不能视作正常模型误检或仅用有限值校验放行，底层故障原因尚未确定。后续批次必须先暂存，逐图与同权重、同尺寸/补边/阈值的独立CPU FP32参照核对；数量或坐标明显分歧时保留证据并暂停该图回写，再重复GPU推理核实，不能按框数截断或调阈值掩盖。CPU仅用于推理计算核查，不改变GPU训练要求，也不把任何预测当人工真值。修复仅追加到仍无人工审核/特殊历史的图，提交时再次检查保护状态；已审图不覆盖，原异常预测日志保留。已完成的模型名/框回读校验只能证明写入一致，不能替代计算稳定性核查。

**跨设备核查的实现入口。** 下表的基础`m3/pred.py`并未自动接入上述guard。实际已验收的暂存、核查和提交脚本位置见01；后续批次先核对这些脚本及保护门槛，不能直接运行基础入口覆盖现有预测。

已有本轮图片时先核对来源、方向、父页身份及名单，缺什么再补什么。新增素材或预标注会写入图片、标签或日志，执行前备份相关旧文件。

选择本轮需要的入口，不依次运行全部命令：

| 要做的事 | 命令示例 | 结果与注意事项 |
|---|---|---|
| m1预标注 | `& $python -B pipeline\m1\pred.py` | 默认补无标签图；已审图始终跳过。加--all可重打未审图，m1没有subset参数 |
| m2预标注 | `& $python -B pipeline\m2\pred.py --subset $predictionList` | $predictionList是本批CSV；已有事件时拒绝重打。可用--weights指定本批候选，不改变部署模型 |
| m3基础预标注入口（本身不含跨设备guard） | `& $python -B pipeline\m3\pred.py --subset $predictionList --weights $m3Weight` | 两个参数必填；只写未审模型建议，已有事件拒绝重打。类别0/1映射为工具5/6，conf0.25、iou0.5、默认imgsz1024；历史n候选显式加--imgsz 640；历史模型须先核对类别与来源，不作为当前部署 |
| 从整页裁出m2图片 | `& $python -B pipeline\cascade\crop.py --stage $stage --parent-list $parentList` | 使用当前m1权重，保留来源与舍弃清单；$parentList可省略，已有裁图或日志不覆盖；同stage分批可用--review-list另存data/m2内的新审核CSV |
| 新增digit/choice素材 | `& $python -B pipeline\cnn\prepare_increment.py --batch $batch --check-only`，核对后去掉--check-only生成 | 可用--subset指定new_name来源CSV；只用普通已审M2框，自动排除各库已有来源，批次拒绝覆盖；旧生成脚本仍停用 |

m1默认conf为0.2；m2预标注固定conf 0.5、imgsz 1024；裁图使用conf 0.2、imgsz 1024、iou 0.5。conf是置信度阈值，imgsz是模型输入尺寸，iou用于抑制重复框。需要改变时先明确理由，不跨环节照搬。

数字批次需要按当前部署M2重裁时，执行 `pipeline/cnn/refresh_digit_crops.py --data <旧未审批次> --batch <新批次名>`；只处理未审批次，新图另存，旧图保留，身份与分区保持。M2检测参数为conf0.5/iou0.5/imgsz1024，数字裁图不额外外扩，不能把重裁当作重新人工审框。

以下API命令说明工具用法，不代表当前获准调用。阶段结束、暂停或中转被拒绝时，以01的有效限制为准，不因整理文档或续跑旧命令自动恢复请求。

三路拼图使用 `pipeline/cnn/grid_prelabel.py`：先运行 `test --data <批次> --selection <file列CSV> --reference <已目视核对的测试结果JSON> --output <新测试目录> --repeats 3`。接口密钥环境变量为MIMO_API_KEY、HAPPY_DEEPSEEK_KEY、HAPPY_GEMINI_KEY，不写入源码或命令示例。测试检查每格编号、标签、截断和结果一致性；疑难空值保持疑难，不作非数字0。

实测通过且用户授权后运行 `full --data <新批次> --output <该批次下的正式预标注目录>`。三路都用24格拼图，当前并发MiMo2/DeepSeek4/Gemini4；中转站Gemini处理其字段内换行，DeepSeek使用8192输出额度，不能照搬单图64/512额度。每批留batches记录、status.json和最终completion.json。相同参数续跑会核对selection.json并跳过成功批次；结果全部收齐才追加未审建议，不覆盖用户已审样本，不启动训练。

人工数字全量审核后的独立API复核使用 `pipeline/cnn/verify_digits.py --data <批次> --output <批次下新复核目录>`，沿用三路环境变量。先以同一96图比较48/64格；成功且各路两种尺寸的读数差异不超过1张才用64格，否则用48格；64格失败但48格三路完整通过时直接退回48格；48格也失败才停止。正式复核批次请求失败会拆成至多24格重试。打乱数字顺序且不向普通复核提供人工答案。首轮三路分工，读数冲突、疑难或裁图异常再发另外两路。特殊样本另附数字小图、M1裁区、整页、定位框、特殊备注及M1类别/状态，三路分别建议。selection冻结人工状态，pilot_summary记录测试，status记录进度，suspects保存疑点与三路结果，special_context/special_votes保存上下文和建议。只写独立复核结果，不改人工日志、M1特殊状态或训练数据；续跑跳过成功请求。

裁图要求、固定身份和禁止覆盖的完整规则见[00第5、6节](00-数据与命名规范.md#5-哪些数据可以进入训练)。拒绝覆盖时先查已有产物，不删除保护文件重跑，不重抽锁定名单。

## 3. 请用户审核本轮图片

代理准备范围和页面，用户确认图片内容。先检查已有服务与端口，只启动本轮需要的工具；使用Edge打开。审核端口按本轮选择，记录到01；训练监控另用固定8901。

下列变量由代理准备：$reviewList为检测审核清单，$digitData为数字样本库，$choiceList为涂黑stem,row清单，$port为审核端口。

```powershell
# 检测框：m1、m2或m3
& $python -B tools\标注工具\serve.py --data (Join-Path 'data' $task) --subset $reviewList --port $port
```

```powershell
# 数字标签
& $python -B tools\数字审核\serve.py --data $digitData --port $port
```

```powershell
# 涂黑答题行
& $python -B tools\涂黑审核\serve.py --subset $choiceList --port $port
```

| 页面 | 用户怎样确认 |
|---|---|
| 检测框 | 改框只暂存，A/D保存并切图，最后一张也保存；←/→只浏览并保留暂存修改。子集名单不动，但保存后显示最新标签；点“刷新分类”或“返回全部”先保存暂存修改，再统一重读分组。分类切换复用当前页。保存失败保留修改、A/D不切图；刷新分类可重试。特殊图修改保存后恢复普通审核，“取消审核”退回未审 |
| 数字 | 按题号密排看图，点图放大；在弹窗输入数字并确认，Enter保存、Esc关闭；0表示非数字。勾选图片后可批量确认，“选中屏幕可见图片”只勾选当前屏幕完整显示且已加载的图片 |
| 涂黑 | 按答案密排全展示，默认划过确认；刷块行列各1至6。点图弹窗选A-F（可多选）修改、确认空白、填特殊标签或撤销；A/D切答案组、F定位未审 |

检测标注顶部“标签显示”可选通用、M1、M2、M3、M4；首次按当前数据集选择，之后记住用户选择。M3只显示填空题大题框（青色）与大题号（红色）；通用显示全部十类，各类颜色贯穿按钮、框和右侧列表。筛选同时限制可选类别及框的鼠标命中，隐藏框仍完整保留并随A/D保存；切换标签显示不提交审核、不切换数据集。单模型的数字快捷键按显示顺序从1重新编号（M3：1大题框、2大题号），通用使用1～9、0；按钮编号同步变化，保存的实际类别编号不变。

检测页“特殊”使用页内窗口填写原因并确认；有“M1裁图错误”快捷原因。提交失败时窗口保留并显示错误，确认成功才改变状态。

检测审核页右侧显示当前图最后一次预标注的模型版本和时间，避免把旧预测误当新候选；未记录来源时明确显示未记录。

检测审核页右侧显示当前图各类框数量，增删、撤销和重做后实时更新；M2的题号、选项即使为0也显示。此处统计已有框，不推测应有数量。重叠框按大框在下、小框在上显示，点击重叠处优先选中小框；后续新增框也沿用此规则。

标记特殊会一并保存当前框和原因，并清除该图已提交的普通草稿。随后浏览、刷新分类不会把它转成普通审核；再次改框后提交审核才恢复普通分类。

涂黑审核页可在当前答案组选择“学科”，例如英语；选择后只显示该组对应学科的图片，可与“只看未审”和疑难/裁图筛选组合，切换答案组或重排时保留学科选择。标题计数针对当前学科，答案组按钮和合计仍是全库统计。新增库使用manifest的subject，旧库从stem中选择题区前的学科识别；旧合卷保留“政史”“地生”名称，不猜测其具体子学科。

增量审核时，数字服务的--data指向 `data/digit/increments/<批次>`，涂黑服务也用--data指向 `data/choice/increments/<批次>`。数字输入允许0至60；涂黑页默认显示已审和未审，每组全部展示；已审原位变绿并淡化，不补图连锁。数字页按用户要求卡片缩为原长宽各一半，每组全部展示，不分200张；默认显示已审与未审，绿色淡化并带勾为已审，A/D切换上/下一个数字，每个数字按钮及标题显示已审/总数和待审数，也可勾选只看未审。旧数字模型只能预测0至34，35至60需要人工看图修正；choice页面题号也只是预测，不作为题号真值。完成的增量批次由snapshot自动发现，仍逐张检查人工审核；新增val/test保持预留。

等图片加载成功再确认。数字页按用户授权默认开启“划过即确认”：真实鼠标移动经过已加载的小图会提交当前标签；快速移动按连续短时轨迹补齐经过的卡片，滚动、切组、离开网格及打开弹窗会断开轨迹，不补审未加载图。每批最多64张合并保存，黄色表示待保存，只有保存成功才变绿；失败红框可点“重试保存”，未完成保存离开页面会提醒。进度使用增量计数，不再每张重建全部分组；小图缓存一小时以改善来回切组。F或“下一个未审”定位漏项。可关闭划过开关。数字页增加行/列滑块，各1至6，默认1×1，可选择4列×5行等审核刷块；鼠标所在图为蓝框左上角，移动时确认扫过刷块内屏幕完整显示且已加载的图，最多6×6，不跨行误选，边缘自然截断。尺寸保存在本机浏览器，下次打开沿用；调整滑块、滚动、切组或打开弹窗本身不确认。点图弹窗可输入特殊标签、保存特殊或撤销审核；特殊图单独分组，不纳入训练。涂黑页复用同样的可调刷块、真实移动轨迹、黄色待保存/绿色成功/失败重试和离开提示；特殊图不划过确认，普通划过不更改已有审核。仅加载、浏览、滚动不算审核。提交失败先处理提示，不能把页面统计当作已审凭据。日志格式和特殊行处理见[00第4节](00-数据与命名规范.md#4-审核怎样才算有效)。

这一阶段的结果应是：范围内标签已由用户确认；暂缓和特殊情况已有明确记录。代理不能代审、补签或为凑数量补抽。

### 涂黑三路拼图预标注与全库复查

使用 `pipeline/cnn/choice_grid_prelabel.py --data <涂黑库> --output <新输出目录>`；加 `--include-reviewed` 可独立复查已审和特殊样本。密钥从MIMO_API_KEY、HAPPY_DEEPSEEK_KEY、HAPPY_GEMINI_KEY读取，不保存密钥。默认冻结12格清单（24格跨路不稳定后改为放大小图、减格测试），48图两次打乱交给三路测试；结构完整、重复及跨路答案差异不超过10%才继续分流全量，否则停止留待核查。此门槛不是人工准确率验收。

拼图不展示旧答案，支持A至F多选、空白和无法识别null；另记疑难、裁图异常和特殊建议。失败批次拆至12格重试并换路，成功批次原位续跑。结果完成在status中为ready_to_apply，仅写独立预测，不自动改人工审核或直接接入训练。已审老库以独立结果对照人工记录，分歧须人工决定；未审批次接入建议前备份日志、暂停同库审核服务以避免并发覆盖，null保留原建议并标疑难，已审和特殊不覆盖。完成后重启审核服务读取新建议。特殊建议只提示，不代替用户特殊决定。

若测试能完整返回但跨路/重复答案仍不稳定，不放宽原来的自动预标注门槛；全库重新核查可改用 `pipeline/cnn/choice_grid_review_all.py --data data/choice --data <增量库> --output <全库独立复查新目录>`。该模式每图分别交给三路，保留全部独立读数及分歧，不自动选择单路或以多数票写真值，不改审核日志。每路按自己的接口保留批次，失败不冒充成功；续跑只补未完成请求。完成后生成results.json、复查结果.csv和completion.json；三路一致也不代表人工审核通过。该模式不受“跨路一致才可自动预标注”的门槛替代影响，因为全程只写独立复查证据，不应用建议。

### 涂黑分工复查与全库审核

若获准采用三路共用队列分工，使用以下入口。`pipeline/cnn/choice_grid_distributed.py --output <已有冻结清单的复查目录> --deepseek-model deepseek-v4.1-flash-1017`复用原selection和成功批次；每批有一路成功就跳过首轮重复请求。疑难标志、与历史答案不同且尚无第二路的批次，再交给另一接口复查。已存在的多路分歧保留给人工，任何结果都不自动审核或写标签。输出distributed_results.json、distributed_completion.json；status.json注明distributed模式，不能再以全库三路齐全率判断完成。旧failed文件是历史证据；本轮失败看distributed_failures.json及status。启动前确认旧全三路进程停止，禁止同目录同时运行两个任务。1017只对本次进程覆盖，不更改数字任务默认模型。


### 全库涂黑同页审核

`tools/涂黑审核/serve.py`可重复指定`--data`合并多个原库，例如`--data data/choice --data data/choice/increments/20261026_多学科已审M2 --port 8925`。不传`--subset`即展示两库全量，保持原划过确认/修改/特殊/撤销交互。图片从各自原库读取，审核事件写回对应原库log，不复制图片或另建训练标签。启动时拒绝跨库同名图片，避免写错来源。单库原命令继续有效。全库复审需先接入独立预标注建议并将历史审核回待审；不要在用户已开始本轮审核后重复重置。批次的进度、备份和来源以01及对应产物为准。

#### 性能与改答案后的提示

`serve.py`侧已做以下性能处理，改交互时不要退回旧做法：后端用HTTP/1.1复用连接，`/img`与`/api/img`读图走192MB内存LRU缓存，`/tree`按状态版本缓存序列化结果并额外返回`preds`。前端`render()`按帧插入（首帧900张、之后每帧300张），单卡由`buildCell()`创建；保存、批量确认、特殊和撤销都只做本地增量更新，不再重拉`/tree`再整页重建。划过采样先收集命中的卡片再统一改DOM，避免每次`elementFromPoint`都与样式变更交替触发强制重排。

实测口径：正式全量A组8276张，切组同步约31ms出900张，渲染期间主线程最长任务约62ms；keep-alive下连续取200张图约0.04秒。改动后仍须用D:/temp下的库副本验证交互，禁止拿正式库做写入测试。

点图改答案后，若新答案落到别的组，原位置不再直接消失，而是保留亮橙黄底、深橙边框的卡片，标签显示`→ X组`并闪一下，顶部提示`这张已移到 X 组`；撤销审核会提示回到哪个组。其余卡片的绿色已审标记、黄色待保存、红色失败重试语义不变。页面按钮行有`重排分组（R）`，也可以按键盘 R：先刷掉未写完的划过保存，再重新读取`/tree`并按最新答案重绘当前组——改过值的卡片会从原来那一组消失、回到它现在所属的分组，橙黄提示块同时清掉。判读冲突或怀疑本地状态与服务端不一致时也用它同步。这个动作只读日志，不写任何审核事件。

## 4. 把本轮数据范围组装一次

检查和实际冻结必须使用同一组参数，避免“检查了A，训练却用了B”。先创建共同参数：

```powershell
$snapshotArgs = @('snapshot', '--task', $task, '--run', $run)
```

m1/m2再加入已核实的阶段和可选名单。以下变量为空时不传对应选项；$stage必须为1至4：

```powershell
if ($task -in @('m1','m2')) {
    $snapshotArgs += @('--stage', $stage)
    if ($snapshotSubset) { $snapshotArgs += @('--subset', $snapshotSubset) }
    if ($deferList) { $snapshotArgs += @('--defer-list', $deferList) }
    if ($decisions) { $snapshotArgs += @('--decisions', $decisions) }
}
```

digit/choice不传stage、subset或defer-list。需要改变准入范围的选项，必须在检查前明确加入：--allow-inferred只用于明确允许的数字推断标签；--skip-invalid只用于明确排除的检测坏标签训练图，不能跳过未审或坏验证图。

**同名subset在不同入口含义不同：**m2预标注限定本批预测，检测审核服务限定本批浏览审核，snapshot表示本批必须检查的名单；快照仍累计纳入指定stage及以前的训练数据。裁图用parent-list限定父页。

## 5. 先检查，再冻结

先运行只读检查。它核对身份、审核、标签、特殊处理和固定验证范围，不写快照、不写共享缓存：

```powershell
& $python -B tools\迭代.py @snapshotArgs --check-only
if ($LASTEXITCODE -ne 0) { throw '数据检查失败，先按报错处理' }
```

报错时回到数据或审核步骤处理，常见原因见第9节。不能为了通过检查而扩大暂缓、换验证集或跳过全部未审。

范围正确、检查通过且用户要求进入训练后，使用同一份参数冻结：

```powershell
& $python -B tools\迭代.py @snapshotArgs
if ($LASTEXITCODE -ne 0) { throw '快照生成失败，不能训练' }
```

成功后核对数量、分区、来源及排除名单。检测快照留下selection.csv、train_list.txt/val_list.txt、labels/train、labels/val和data.yaml；snapshot_audit.json在run目录下。CNN只留selection.json，不复制图片。检测训练和评估实际读取本run的快照标签。已有快照不覆盖；复用时直接进入训练步骤，不再次执行snapshot。旧run缺现行审计时保留原样，不补造，也不删旧现场。

## 6. 训练，并确认监控显示本轮

先检查固定监控地址 `http://127.0.0.1:8901/`。已有服务不重复启动；确需启动时使用：

```powershell
& $python -B tools\训练监控\serve.py --run (Join-Path 'train' $run)
```

用Edge核对页面上的实际run。监控在无指标或指针不可用时可能显示其他训练，不能只看页面打开就算正确。

监控在上一次请求结束后等待1.5秒再刷新，请求超过8秒会超时重试，不堆积请求。顶部“最近刷新”表示接口更新时间；“每轮指标”来自results.csv，只在一轮验证结束后更新。当前轮步数及剩余时间另从训练日志读取，支持秒、分秒和时分秒格式；训练是否活跃优先看当前run心跳，不能把指标暂未变化当成页面未刷新。更新监控代码后只重启监控服务，并刷新已有监控页，不中断训练或刷新审核页。

“训练错误与警告”只读提取当前run的train.log、train.err.log、supervisor_error.json、completion_check.json及numerical_failure.jsonl，支持筛选、展开原文和复制错误。累计次数覆盖日志已识别事件，列表显示最近40条，重复输出可重复计数，不代表独立故障数；文本匹配不能保证捕获所有错误。来源文件/行号便于回查，数值保护原文保留故障阶段、轮次和样本路径。AMP可恢复溢出在“数值保护记录”单独计数，不算致命错误。面板为空不等于训练已验收，完成仍核对退出码、权重和completion_check。

显式传`--run`时监控固定该训练，支持扫描目录内的短运行名、`train/<run>`或绝对路径；首轮指标未出也不回退旧run。页面HTTP200只代表HTML可读，还须核对`/api/state`的实际run、总轮数、心跳和指标；已有指标时应为`ok=true`，不能把接口内部错误当正常启动。涂黑训练显示验证集“整行答案全对率”和“选项判断准确率（A–F）”，数字训练显示top-1，检测训练显示mAP和召回率。CNN总轮数读取training_args.json；涂黑每轮日志提供耗时，剩余时间按最多轮数估算，早停会提前结束。完成状态以退出码和完整性检查为准。

通常沿用当前权重微调，由统一入口启动、检查产物并永久留档：

```powershell
& $python -B tools\迭代.py train --task $task --run $run
```

M2全精度数值异常排查可再传 `--deterministic` 固定计算路径并关闭TF32；仍须以实际复现和故障记录判断，不据此宣称稳定性已验收。

检测数值异常排查可显式传 `--no-amp` 改用FP32全精度，数值保护保持开启；是否启用以本轮实际参数为准。

BN统计量等数值故障保留现场后，可显式加`--no-cudnn`对比原生CUDA计算路径；该开关不关闭数值保护，也不证明故障根因已确定。失败run中的有限最佳检查点只有逐值检查后才可用作另一个新run的起点，不能把失败run改报成功或恢复损坏优化器。

检测模型继续上一轮候选时加 `--initial <候选权重路径>`，实际起点记录在launch.json，不改变部署；省略时沿用当前部署权重。

只有明确选择CNN从头训练才加--scratch。起点缺失或加载失败应停止，不能自动改为随机初始化。数字从旧35类权重微调时自动扩为61类，保持旧类别输出行，新增35至60行使用本轮初始化；其他层仍严格核对形状。统一入口没有断点恢复参数。

日常不要直接运行底层train_base.py，它的默认值与统一入口配方不同。需要调整训练时，参考下表，并先明确本轮方案：

涂黑训练可显式加`--english-repeat 3`：训练分区中stem含`.英语.`的每张图每轮精确抽取3次，其余图1次，顺序重新打乱且每次独立增强。原始图、日志和验证集不变；run内sampling.json记录唯一训练量、英语数量及每轮抽样量。默认1维持原配方。

英语专用实验：snapshot检查与冻结都加`--subject 英语`，只使用已审英语并排除与固定val同原始页的训练区域，原始分区不改。训练`--architecture flat --scratch`为旧结构从头对照，`--architecture sequence --scratch`为横向序列结构从头训练；后者横向下采样4倍，使用双向GRU及A–F查询聚合，仍输入48×192整行并输出6个选项logit。两者使用相同快照、预处理、采样和训练参数；旧架构权重不能直接载入新结构，必须明确scratch，不自动回退。

`pipeline/cnn/eval_choice.py --data <快照目录> --weight <名称> <TorchScript权重> --output <新JSON路径>`可重复指定weight比较同一固定val；可选`--layouts <JSON>`提供目视核对的选项数量（items为文件名到数量的映射），未核对样本归unknown，不凭manifest中n_opts=6或图片宽高比当真值。报告分选项数量与来源的整行全对率及逐图错误。固定val参与选模，不能称为独立测试；英语专用权重只永久留档，学科路由部署另行决定。

| 项目 | 统一入口默认值或处理方式 |
|---|---|
| 模型 | m1用yolo11n；m2/m3默认yolo11s、输入1024；M3历史n/640候选继续保留可检查 |
| 最多训练轮数epochs | 检测80、digit 40、choice 60 |
| 每批样本数batch | m1/m3 8、m2 4、digit 256、choice 32 |
| 学习率lr | 检测1e-4、CNN 1e-3；检测--lr映射为底层lr0 |
| 检测配方 | AdamW优化器、warmup 3、AMP开启、scale/translate为0；m2不水平翻转 |
| 显式调整 | --epochs、--batch、--lr；不支持--arg透传替换数据等参数 |

学习率决定每次参数更新的步幅；warmup表示开始时逐步增加学习率。AMP等术语见[03](03-项目原理.md#7-为什么要保护数值和方向)。默认值是准备方案的起点，不是实际执行凭据。

实际记录看run中的launch.json（命令与起点）、training_args.json（训练器解析参数）、results.csv（指标）。缺记录时不能用默认值补成“已执行”。旧--no-deploy参数仅兼容保留，不传也不会自动部署。

随时只读查看指定run：

```powershell
& $python -B tools\迭代.py status --run $run
```

不传run时读取最近指针train/.last_run.json；没有指针是正常提示，不代表没有历史。跨任务始终显式指定run。

已停止任务收尾时核查best/last是否仍含完整优化器状态，按[00的文件规则](00-数据与命名规范.md#2-名字怎样保留来源)精简并留来源记录；正式候选、标签名单、指标和故障批次保留。

已清理的旧run可能不再保存普通best/last。先读`checkpoint_pruning.json`确认删去的文件、原因和保留权重位置，再按`candidate.json`找到models中的永久候选；不要因旧weights目录缺文件而认定永久候选丢失，也不能承诺恢复已删除的训练状态。`checkpoint_compaction.json`记录的是精简，`checkpoint_pruning.json`记录的是删除，两者可能先后存在，以文件现状与删除清单共同判断。

## 7. 检查候选，再比较效果

先确认训练产物正常：看exit_status和completion_check，核对数值及权重检查是否通过。通过后，candidate.json记录永久候选路径和指纹。目录存在、训练退出或出现best.pt，都不能单独证明成功。

人工主动停训要另查`manual_stop.json`和`manual_stop_check.json`：记录停止原因、完成轮数及候选逐值检查，保留原非零退出码和`completion_check.success=false`。检查点通过检查与训练正常完成是两件事；保留的候选不自动获得部署资格。

再用相同样本范围比较新旧模型。检测评估可用于m1/m2/m3，权重与快照类别必须对应；M3新s候选评估加--imgsz 1024，历史n候选按原工作规格加--imgsz 640；对照必须分别注明模型和输入大小。先准备$oldWeight和$candidateWeight实际路径，再执行：

```powershell
$snapshotYaml = Join-Path (Join-Path 'train' $run) 'dataset_snapshot/data.yaml'
$oldResults = Join-Path (Join-Path 'train' $run) 'eval_old'
$newResults = Join-Path (Join-Path 'train' $run) 'eval_new'
& $python -B pipeline\m1\eval.py --weights $oldWeight --data $snapshotYaml --results $oldResults
if ($LASTEXITCODE -ne 0) { throw '旧模型评估失败，保留现场' }
& $python -B pipeline\m1\eval.py --weights $candidateWeight --data $snapshotYaml --results $newResults
if ($LASTEXITCODE -ne 0) { throw '候选评估失败，保留现场' }
```

评估会写产物。--results必须是新目录；显式--json也必须是新文件，不能覆盖。默认汇总分别写入各结果目录的metrics.json。

上述`pipeline/m1/eval.py`当前固定使用GPU0，没有CPU设备参数。若本轮要求CPU FP32同口径比较，应核对01中已有的评估脚本和快照配置另行执行，不能把此命令记成CPU评估，也不能假设它带有跨设备guard。

M3边缘回归除框数、IoU和mAP，还要逐图检查大题号、分值和作答内容是否被裁掉。出现分歧先核对源日志→冻结标签→原图预测坐标，区分标签、显示和模型偏差；不能用“匹配成功”代替内容完整性验收，也不能把预测吸附到人工框冒称修好。报告保存叠框图和逐边像素差，是否增加自动覆盖指标另行实施。

向用户报告模型版本、样本范围、统计单位、日期和来源，并检查各学科及本轮针对的错误，不能只给一个总指标。choice同名单比较使用下述eval_choice.py；digit尚无专用新旧比较命令，训练指标不能冒充独立比较结果。

### 整页到M2和选择题识别的回归验收

报告按“手标 / 当前部署 / 候选组合”三列对照，各列写明权重；左侧原图每次只显示一组来源，点击题目可定位放大。灰、蓝、紫表示来源，红绿表示与手标的差异。只更新展示、不重新运行模型时，执行 `& $python -B pipeline/chain_report.py <已有报告目录>`；保留原 `results.json` 和审核记录。

`pipeline/eval_chain.py`从已转正的`data/m1/images`工作页开始，运行当前M1、重新裁区、当前M2、配对与题号/涂黑识别；不替换流水线部署。它按原学科（历史/道法、地理/生物分别统计）抽不同卷组，验证优先，原分区保持。需要已审M1/M2、人审答案，以及可定位的已审题号小图；旧manifest里的题号预测不作真值。

```powershell
& $python -B pipeline/eval_chain.py --output models/对比/m2/<新报告目录> --per-subject 15 --candidate-digit <永久题号候选> --candidate-choice <永久通用涂黑候选> --english-choice <永久英语专用候选>
```

输出目录必须不存在。冻结selection.json，逐页保存pages/*.json、images/*，最终生成results.json、summary.md、index.html和completion.json。可用Edge打开报告；如需本地HTTP浏览，在该目录启动仅监听127.0.0.1的静态服务。报告的“当前”和“候选”共享同一组M1/M2预测；候选英语路由只在此次对比中使用，不修改current.json。逐页展示人工框、预测框、全部人工参照答题行与两套读数；漏配计失败，未知真值不计正确。严格门槛要求人工参照完整、题号与答案全对、无漏框/多框/额外配对；实际可用率（含valid）另外保存，不能用阈值筛走错误后重算。

此入口是已审数据回归验收，必须报告训练/验证身份，不能冒充独立泛化测试；原始扫描方向转正不在本入口验收范围。M3进入训练前仍须核对其真实标注、审核状态、固定分区和训练入口，不能把M1/M2通过当成M3数据已就绪。

报告中的“错误”首先是与当时人工记录不一致。用户发现误标后在源审核页修正，未来对比使用新的独立输出目录；不要修改原结果分母、覆盖旧快照或自动采用模型答案。界面中的当前部署、候选组合和手标分别列出，候选更好也不表示已经部署。

## 8. 用户同意后才部署

先向用户说明对比结果、候选版本和拟替换的模型。取得明确同意后执行：

```powershell
& $python -B tools\迭代.py deploy --task $task --run $run
```

工具重新核对任务、来源run、候选路径和指纹，再更新部署别名与current.json。CNN使用models/cnn/digit.pt、choice.pt别名，历史版本保留。

status显示可部署，只代表记录通过程序检查，不代表已获用户授权。旧完成记录缺success/candidate时标为legacy，不能直接部署；先明确验证或迁移方案。不改DEFAULTS、不直接覆盖pt文件替代这一步。



## 9. 失败后从哪里查

| 提示或现象 | 先查什么 | 怎样继续 |
|---|---|---|
| 未审、暂缓项已审、特殊处理变化 | 日志、本轮名单 | 完成实际审核，或更新日志里的特殊处理 |
| 审核没写进日志、图片缺失 | 日志文件和图片路径 | 重新提交审核；图片缺失先补图 |
| 父页身份未知、固定验证变化 | 来源、splits、验证基线 | 找回可信身份；改变基线须用户决定，不随机重分 |
| 非法类别、明显越界、坏图 | 原图片与人工标签 | 在源审核处修正，不手改快照 |
| 数字标签未确认或变化 | 当前标签及review记录 | 用户确认当前图片和标签 |
| NaN、异常指标 | numerical_failure、failure_batch、diagnosis | 保留异常批次证据，分析原因，不填零 |
| 训练退出但无候选 | exit_status、completion_check的error | 按失败原因处理，旧现场保留 |
| 权重加载失败 | 路径、指纹、权重结构 | 修复起点问题，不改成随机初始化 |
| 页面不更新或显示别轮 | run、heartbeat、实际进程 | 确认服务对应本轮，再继续观察 |

查看训练指标用监控，不用可能锁文件的表格软件打开results.csv。遇到故障先保留现场，不能未经核实就认定数据坏了。

## 10. 保存进度和换窗口

用户只需说 **“我要换对话框”**。本节由代理执行：把仍有效的信息整理为完整01，调用工具保存并当场归档到06，最后读回核对。记录成功不代表业务问题都已解决。

### 准备完整摘要

重读原01。保留有效状态、决定、限制、未决问题；已解决或替代的写明去向。正文是完整新版本，不是只写本轮增量。编号、决定原文和关闭规则见[00第7节](00-数据与命名规范.md#7-文档怎么维护)。

在本次D盘临时目录中准备summary.txt，使用以下结构；前五节必有，没有条目写“无”。有关闭内容再加第六节。

```text
接力结构：2

当前状态：
- [S001] 当前结果，以及理解它所需的范围或证据。

有效决定与限制：
- [D001] 决定、适用范围及依据。

未决问题：
- [Q001] 什么未解决，影响什么，缺少什么决定或验证。

本轮必要记录：
- 对下一窗口有用的新事实。

证据：
- 实际产物位置。
```

同一窗口使用稳定session：优先用平台会话ID，取不到就生成一次并保存为session.txt；后续更新复用，新窗口换新ID。不要照抄旧窗口ID，也不要每次提交生成新ID。

节与节之间空一行；同一节的条目之间不插空行。当前状态写已经核实的结果，未决问题写仍缺什么；不要把未决问题或“下一步”当成用户已经授权的新任务。

### 预检、提交、读回

下例的$scratch是已建立的本次D盘临时目录，summary.txt已写好；示例使用session文件回退。普通进度更新也走此流程，但去掉--handoff，并且不要求archived=true。

```powershell
$python = 'D:\Dev\Python\3.13.6\python.exe'
$summaryPath = Join-Path $scratch 'summary.txt'
$sessionFile = Join-Path $scratch 'session.txt'
if (!(Test-Path -LiteralPath $sessionFile)) {
    [guid]::NewGuid().ToString() | Set-Content -LiteralPath $sessionFile -Encoding utf8
}
$session = (Get-Content -LiteralPath $sessionFile -Raw).Trim()
$before = & $python -B tools\写快照.py --inspect | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or $before.parse_ok -eq $false -or $before.history_ok -eq $false) {
    throw '当前记录异常，保留现场，停止覆盖'
}
$oldHash = $before.sha256
& $python -B tools\写快照.py --session $session --note-file $summaryPath --expected-sha256 $oldHash --dry-run
if ($LASTEXITCODE -ne 0) { throw '预检失败，未提交' }
$saved = & $python -B tools\写快照.py --session $session --note-file $summaryPath --expected-sha256 $oldHash --handoff | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw '交接失败，按工具提示的阶段处理' }
$after = & $python -B tools\写快照.py --inspect | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or !$after.parse_ok -or !$after.history_ok -or !$after.archived -or $after.sha256 -ne $saved.final_sha256) {
    throw '读回或归档不符，不能回复交接完成'
}
```

代理还须读回正文，核对真实状态及有效决定完整。工具验证字节和结构，不能替代理判断事实。

| 异常 | 处理方式 |
|---|---|
| 哈希与预检不同 | 重读01、重新合并；不能只换哈希强写 |
| 01已保存但归档失败 | 按阶段重试相同正文，工具补归档并避免重复 |
| 首次没有01 | 使用inspect返回的missing基线，不手造空文件 |
| 真正的旧格式01 | 仅首次用--migrate-legacy迁移；完整旧文归档，损坏结构不能冒充旧格式 |

完成后回复“交接完成”，简述仍待处理事项。新窗口读取README、AGENTS和01，再按用户新指令继续。

维护交接工具时，用 `& $python -B tools\验证交接与准入.py --workdir (Join-Path $scratch '交接验收')`；默认只跑现行交接场景A/B/E/F/H。旧数据准入和前端绑定场景已退休，不作为现行验收。

维护CNN数据流时，用 `& $python -B pipeline\tests\test_data_flow.py`。两者均使用临时副本或假数据；模拟交接、真实浏览器操作和完整训练的验收结果分别说明，不能互相代替。
