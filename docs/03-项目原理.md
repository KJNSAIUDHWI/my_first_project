# 项目原理

这份文档解释自动改卷的整体方案。想执行任务，请读[操作手册](05-迭代操作.md)；想知道哪些环节目前可用，请读[当前进度](01-接力记录.txt)。下面描述的是完整设计，不代表全部已经接通。

## 1. 从扫描图片到每题得分

自动改卷依次解决四个问题：图片是否摆正、答案在哪里、写了什么、应该得几分。

```text
扫描答题卡
  → 摆正图片
  → m1：找到姓名学号区、选择题区、填空题区
      ├─ 姓名学号区 → 读取身份信息
      ├─ 选择题区 → m2：找到题号和选项
      │              → 配对 → 识别题号和涂黑组合 → 得到选择题答案
      └─ 填空题区 → m3：找到大题及大题号
                     → 配对大题与题号、读取印刷题号
                     → 大题裁图交给多模态LLM API转录手写文字与公式
  → 对照标准答案与评分规则
  → 每题判分，汇总成绩
```

m1至m3负责逐级区域检测，回答“在哪里”。填空大题内部的小题与空位由手写转录接口按卷面题号组织，当前不设置额外的小题框检测模块。识别生产入口已接通，当前先验收20页识别，标准答案与评分后接。填空答案的手写文字和公式交给多模态LLM API转录，不能用早期针对印刷体的OCR结果代替手写方案验收。题号和涂黑识别负责回答“是什么”。评分还要使用标准答案与评分规则。因此，检测到框、读出答案、算出分数，是三个不同的结果。

逐级处理能减少无关背景和版式差异，也便于单独改进一个环节。例如选择题漏答，原因可能是上游裁图漏了内容，不一定需要重训识别模型。排查时先看该环节实际收到的图片，再往前找原因。

填空手写转录已选定豆包 Lite 的非思考模式。输出按“大题号 → 小题号 → 空序号”定位每个答案；明确划掉或涂黑的内容忽略，最终答案无法辨认时返回“看不清”，未作答或仅删除未重写时保留空字符串。学生保留的错字、数字和公式忠实转录，评分另行处理。当前识别链路将大题按独立图块编号紧凑拼入约1500×1500方图，使用high和4并发，温度省略沿用服务默认；实验子层级如(1)①保存为1.1，不以重复JSON键混合。每块可追溯原卷与实际拼图，空白、看不清、结构失败分别保留，仍需人工复核。

用户已明确要求：填空或实验探究的小题只要出现图片、示意图、曲线图或其他图形，整个小题保留题号并标记“舍弃”，不识别其中的文字答案；不局限于需要学生作图的小题。同大题其他无图小题继续识别。“舍弃”不同于空白、看不清或请求失败，不让后续空位前移。

## 2. 为什么选择题还要配对

检测出来的题号框和选项框只有位置，没有“第几题选了什么”的含义。配对程序先筛选纵向重叠、题号位于选项左侧且距离合理的候选，再做一对一分配。缺框时允许不匹配，不强行用其他行或其他列的框补齐；再分别识别数字和涂黑组合。

题号分类把局部图读成数字，涂黑识别把一行读成选项组合。位置配对和题号连续性可以提供辅助证据，但缺框、跳号、多列排版会破坏简单顺序假设，因此不能强行补齐；原始识别与辅助修正应可追溯。

## 3. 为什么用日志保存审核结论

模型预测和人工确认提供的依据不同。项目用每张图、每条答题行自己的中文日志，保存预标注、审核、特殊处理和撤销，再按事件先后恢复当前标签及状态。页面上的计数、CSV中的旧标签和模型预测，都不能代替日志里的人工结论。

编辑中的内容与已经提交的人工结论不同。图片与日志保留稳定来源关系，撤销和特殊处理也必须可追溯。具体提交行为和准入约束由[00](00-数据与命名规范.md)定义。

日志记录的是人工当时的判断，也会有误标。模型与日志不一致不必然是模型错，应同时检查原图、上游裁区、实际输入和人工答案。评估报告据此使用“一致率”；用户接受当前效果可以结束该阶段，仍保留未处理的少量问题及原始测量结果。

## 4. 为什么固定分区和验证集

同一张卷的正反面、重复扫描、局部裁图往往高度相关。如果分散到训练和验证中，模型可能因为见过相似内容而得到虚高成绩。

项目为关联图片保留同一卷组身份，裁图继承父页身份，再按固定名单区分训练、验证和独立测试。新增图片不能随意随机重分，也不能因身份不清而临时指定一个分区。

每轮验证必须冻结到具体图片，才能比较新旧模型。各模块固定或扩展验证范围的具体规则见[00](00-数据与命名规范.md#5-哪些数据可以进入训练)。名单变化后，要在同一新名单重评旧模型，不能直接比较旧分数。框数相同也不等于框位置准确；历史单科回测同样不能代表跨学科能力。

框的IoU衡量区域重合程度。大框即使IoU很高，也可能因为少覆盖一条窄边而漏掉题号或答案。因此，填空裁区还要检查整题内容是否保留；mAP、box loss和实际裁图完整性不能互相替代。

使用DFL的检测头，把锚点到框边界的距离表示为有限个距离档位。不同预测层的每档对应不同像素数，因此必须逐层、逐锚点检查能否表示完整真值，不能只看最大层的范围。训练若把宽框分给距离不够的锚点，目标距离会被截断；多训练或补相似图片未必能消除这种边缘内收。范围约束分配实验在选正样本前检查四边距离，仍需比较漏检和整体效果。

## 5. 为什么每轮冻结一份数据

审核数据还会继续修改，训练却必须能回答“这一轮究竟用了哪些图片、什么标签”。因此每次训练先保存独立名单和当时的标签。检测任务把标签写到本run的快照目录；数字和涂黑任务把标签或答案写入selection.json。图片直接读data原图，不另复制。

训练和独立评估读取本run的快照标签，不读共享labels里的旧导出结果。后续审核不会改写已经冻结的标签。名单、标签、训练参数、起始权重、运行日志和最终候选共同说明这一轮的来源与结果；不能直接使用共享旧dataset代替本轮快照。

具体文件和校验规则见[00第5节](00-数据与命名规范.md#5-哪些数据可以进入训练)。

## 6. 为什么训练成功还不能直接部署

训练正常退出，只说明程序跑完。权重可加载、数值有效，是产物检查；是否值得替换，还要在同一验证范围比较新旧模型，并检查各学科和本轮关心的错误。

项目把候选留档与部署分开：每次通过检查的候选永久保存，用户决定后才替换实际使用的权重。登记文件记录当前模型的路径、指纹和来源运行，避免根据文件名猜“最新版”。

微调是在已有权重上继续学习；从头训练从随机参数开始；断点恢复还需要优化器等训练状态。这三种方式不能混称。起点缺失时应停止，不能悄悄改为从头训练。

## 7. 为什么要保护数值和方向

训练中的NaN、Inf表示数值无效，可能继续损坏模型或评估结果。程序应保存出错批次和异常阶段，帮助判断原因，不能填零掩盖，也不能直接认定那批图片就是坏数据。

混合精度训练有时会出现可恢复的梯度溢出，需要与权重已经损坏区分。相关技术缩写放在下表，需要排查时再查。

BF16提供更大的数值范围，但表示细微坐标变化的精度低于FP16。因此可以用BF16计算网络特征，同时把距离分布积分、任务分配及几何损失保留为FP32。更换精度必须检查实际模型的有限性、梯度和CPU参照差异，不能把一次短测通过当成长训稳定，也不能关闭数值保护。失败时保存当时的原始参数和BN状态，上一轮正常检查点不一定能复现当前故障。

单个梯度有限，不保证用FP32计算平方和时不会溢出。梯度范数可用FP64聚合，再分步缩放到原裁剪上限；NaN/Inf仍拒绝。这能避免一种数值计算风险，不能单凭此认定实际GPU故障根因已找到。

训练现场完成授权清理后，旧run只保留权重和最小来源记录；历史报告中提及的快照、故障输入或日志可能已不存在，须结合清理清单解读。固定验证身份独立保留，清理训练现场不会重新划分数据。

图片方向影响所有下游坐标。方向模型输出的类别要映射为角度；看图时旋转，不一定改变实际像素。不同图片库对照片方向标记的处理也可能不同，比较框和裁图前必须统一。

| 术语 | 在本项目中的含义 |
|---|---|
| YOLO | 定位矩形区域的检测模型；m1、m2等使用这类模型 |
| CNN | 卷积神经网络；这里主要指题号、涂黑和方向分类模型 |
| AMP | 混合精度训练，用较低精度加速部分计算 |
| BN | 批归一化层；其中的统计值也需要检查是否被异常数值污染 |
| EXIF | 图片元数据；其中的方向标记会影响图片读取方向 |

## 8. 一轮迭代怎样改进模型

从一个具体错误出发，先保留旧模型和评估范围，再补有针对性的数据。人工审核后冻结、训练、保存候选，在相同范围比较结果，最后由用户决定是否部署。

比较中发现的新错误，再回到下一轮数据准备。这样才知道改进来自哪里，避免只反复训练而没有解决原来的问题。

公式转录要求忠实保留分式、上下标、根号和符号，以美元符号包围LaTeX；原始JSON中LaTeX反斜杠必须双写，避免合法JSON控制转义损坏命令。提示词提供可解码示例，不按学科常识补正公式。局部涂改先区分旧字与重写，禁止拼接；无法确定保留内容时标看不清。提示词规则不代表模型已稳定遵守，仍需真实错例及人工验收。
