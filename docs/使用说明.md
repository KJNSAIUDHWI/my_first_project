# 使用说明

## 环境与依赖

已使用的开发环境为Windows x64、Python 3.13.6。完整识别默认在CPU上运行；豆包转录需要网络和火山方舟API密钥。

下面是对应开发环境的安装参考。在项目根目录执行，建议使用独立环境：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --extra-index-url https://download.pytorch.org/whl/cu124 torch==2.6.0+cu124 torchvision==0.21.0+cu124
python -m pip install ultralytics==8.4.96 numpy==2.3.5 opencv-python==4.11.0.86 Pillow==12.3.0 PyYAML==6.0.2 scipy==1.16.3 pandas==2.3.3 matplotlib==3.10.7 psutil==7.2.2 tqdm==4.67.1
python -m pip install paddleocr==3.7.0 paddlex==3.7.2 onnxruntime==1.31.0 safetensors==0.8.0
```

以上版本来自已运行环境，未做全新环境安装验证。Paddle题号通过ONNX Runtime运行，无需额外安装PaddlePaddle。不要同时手动安装多个提供 `cv2` 的OpenCV发行包。

## 恢复部署权重

下载[weights目录](../weights/)中的全部 `.7z.001` 至 `.7z.004` 分卷，放在同一目录。使用7-Zip打开第一卷，输入项目持有人提供的密码，解压到项目根目录。

解压后应出现 `models/` 目录及包内的 `部署清单.json`。其中包括方向、M1、M2、M3、数字、涂黑模型，以及Paddle题号模型、配置与部署注册表。

分卷校验值见[SHA256SUMS.txt](../weights/SHA256SUMS.txt)，部署文件及哈希见[部署清单](../weights/部署清单_20261101.json)。命令行校验与恢复步骤见[权重说明](../weights/说明.txt)。

## 配置豆包API

在项目根目录创建 `.env`：

```dotenv
ARK_API_KEY=your_ark_api_key
```

也可以设置 `ARK_API_KEY` 环境变量；环境变量优先于 `.env`。`.env` 已加入Git忽略规则。

客户端使用 `doubao-seed-2-1-lite-260915`，关闭思考模式，图片精度为 `high`，采用非流式返回。需要在火山方舟账户中开通对应模型。接口地址及提示词位于 `pipeline/common/recognition_api.py`。

## 运行识别

输入目录放置 `.jpg`、`.jpeg` 或 `.png` 图片，逐张按页处理；不会递归扫描子目录。

```powershell
python -B pipeline/run.py --recognize --input "../papers" --out "../grading-results/run-001" --concurrency 4
```

| 参数 | 用途 |
|---|---|
| `--input` | 自己的图片目录；克隆仓库后需显式指定 |
| `--out` | 本批输出目录，建议每批使用新目录 |
| `--working-images` | 图片已转正，保留原像素，仅检查方向 |
| `--concurrency` | API任务并发数，1至8，默认4 |
| `--detect-only` | 只执行本地检测与拼图，不请求豆包 |

同一批输入、代码与模型保持一致时，可重复使用相同命令和输出目录恢复处理。输入、检测代码或模型发生变化时，使用新的输出目录。程序会校验清单，避免混用结果。

## 查看与核对

```powershell
python -B tools/识别验收.py --dir "../grading-results/run-001" --port 8903
```

在浏览器访问 <http://127.0.0.1:8903/>：

- 总览可按待核对、未检查筛选试卷。
- 左侧原卷支持滚轮缩放、拖动平移和选择答案叠加；点击检测框定位题目。
- 右侧显示原始裁图和逐空答案，可切换只看选择题或填空题。
- 点击“实际拼图”查看发送给豆包的图像及图块编号。
- Esc依次关闭大图、恢复整卷、返回总览；F或“整卷复位”恢复原卷视图。
- 人工反馈支持正确、识别错误、漏题／漏空、对应错误、看不清，并可填写正确转录。草稿保存在浏览器中，点击保存后写入本批结果目录。

## 输出与常见问题

输出目录包含 `results.json`、输入与模型清单、页面图片、裁图、拼图、API响应及人工反馈。查看结果通常使用验收页面，无需手动打开JSON。

| 现象 | 处理方式 |
|---|---|
| 缺少模型文件 | 检查权重是否解压到了项目根目录，以及分卷是否下载完整 |
| 未找到可识别的答题区 | 当前处理选择题、填空及实验题；检查原卷类型、方向和图片清晰度 |
| 未配对 | 查看题号框与选项／大题框的位置，可在人工反馈中记录对应关系 |
| 未检出选中项 | 对照原图检查是否未作答或涂痕较浅，展开识别详情查看分数 |
| HTTP 401／403 | 检查API密钥与模型权限 |
| 账号用量／费用限制 | 在平台账户中检查额度与模型状态，解决后用相同命令续跑 |
| 公式显示失败 | 页面保留原始转录并显示原因；检查转录格式和公式资源是否加载成功 |

首次启动验收服务会从npm下载固定版本KaTeX资源到本批输出目录，之后可复用；外网不可用时可先查看原始转录。
