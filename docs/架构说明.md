# 架构说明

## 各环节职责

| 环节 | 职责 |
|---|---|
| 方向模型与小角度校正 | 检查页面方向，新扫描图执行旋转与倾斜校正 |
| M1 | 划分身份、选择题和填空／实验答题区 |
| M2 | 检测选择题题号框和选项行框 |
| 配对与题号识别 | 按几何位置做一对一匹配，Paddle读取印刷题号 |
| 涂黑模型 | 读取整行选项，支持多选组合 |
| M3 | 检测填空／实验大题及大题号框 |
| 拼图与豆包 | 独立编号裁图、紧凑装图、逐空手写转录 |
| 验收页 | 将转录与原卷区域、实际API输入对应展示，并保存人工反馈 |

完整识别入口为 `pipeline/run.py --recognize`。其他分模块入口仍可供开发使用，默认数字CNN与完整识别中的Paddle题号适配器并存。

## 拼图与转录

大题裁图按空间紧凑装入约1500×1500方图。保持比例、不拉伸、不裁掉内容；过大裁图按比例缩小。填空与身份图块分开打包，默认4个API任务并发。

每个图块具有独立ID，与原页、原裁图及拼图坐标对应。即使不同页面存在相同题号，也不会按题号合并结果。

填空结构为“大题号 → 小题号 → 空序号”。印刷子题号如 `(4)①`、`②` 分别表示 `4.1`、`4.2`，每个子题的空号从1开始。没有印刷子题号的多个填空仍归同一小题。

当前提示词要求：

- 忠实转录学生最终保留的文字、数字和公式，不解题或改正答案。
- 删除笔迹与重写内容分开辨认，不把旧字与新答案拼接。
- 真正空白保留空字符串，看不清明确标记；请求失败与缺失输出单独记录。
- 使用LaTeX表达公式，JSON中的反斜杠正确转义。
- 含任何图片或示意图的小题整体标记“舍弃”，其余无图小题继续识别。

当前仍有涂改拼接等错例，验收页保留原图与转录，便于逐题修正。

## 匹配与异常

题号与答题框先筛选同排、左右位置和间距，再通过匈牙利算法做一对一匹配。多选标记会占用题号后的空间，配对规则已为这类间距保留余量。缺少对应框时保留未配对项，不按顺序补题号。

低置信度、未配对和重复题号在页面标为待核对。HTTP错误、读取失败、公式显示失败等运行错误显示具体环节及原因。

## 保存与恢复

输入图片、当前部署模型和检测代码通过清单及哈希绑定输出批次。API成功响应按请求指纹缓存，返回的usage和原始内容保留在结果目录。结构异常的图块只做一次定向补跑；账号权限或用量限制会停止后续请求。

人工反馈保存在该批结果中，通过修订号避免多个页面相互覆盖；浏览器草稿与已保存反馈分开。反馈不会直接成为训练标签。

正反面作为独立页面处理，没有身份区则跳过身份识别。目前不自动合并学生身份，不生成成绩或导出评分表。
